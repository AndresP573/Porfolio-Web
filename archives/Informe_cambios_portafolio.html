Portfolio web: cambios en HTML, CSS, JavaScript y backend

Historial de la estructura, el diseno, la interactividad y la base de datos.

28 de octubre de 2026

Resultado: se mejoraron la estructura y el diseno responsive del portfolio, se agregaron habilidades y validaciones para el formulario, y luego se conecto el contacto a un servidor Node.js con una base SQLite local.

HTML: estructura y contenido

El documento sigue con lang="es", codificacion UTF-8 y viewport para mobile. Se renombro el titulo principal y se agrego una meta descripcion para mejorar la pagina.

  • Se mantuvo la navegacion con las secciones #sobre-mi, #proyectos y #contacto.
  • Se agrego una seccion de habilidades dentro de “Sobre mi” para dar mas contexto del perfil.
  • Se ampliaron los proyectos a tres tarjetas para que la pagina se vea mas completa.
  • Se añadieron tooltips sobre cada habilidad para explicar su tecnologia al pasar el cursor sobre ellas.
  • Se mantuvieron etiquetas y campos del formulario vinculados con for e IDs.
  • Se agrego novalidate para controlar la validacion con JavaScript y evitar mensajes nativos del navegador.
  • Se corrigieron textos visibles para dejar el contenido sin tildes, sin perder la legibilidad del proyecto.

CSS: diseno visual y adaptacion

La hoja de estilos se reforzo para dar una presentacion mas pulida y con mejor ritmo visual.

  • Se agrego un fondo suave con degradado y sombras ligeras para mejorar la apariencia general.
  • Se creo un layout de dos columnas para la seccion “Sobre mi” con una caja de habilidades.
  • Se anadieron efectos hover en proyectos y mejor espaciado para dispositivos pequenos.
  • Se ajustaron media queries para que la seccion de proyectos y la cuadricula de contenido se adapten mejor a pantallas estrechas.
  • Se mejoraron los estilos del boton y el estado del formulario para que se vean con mejor contraste.

JavaScript: validacion, envio y feedback

  • Se mantiene el año dinamico en el footer con new Date().getFullYear().
  • Se valida el nombre, correo y mensaje antes de aceptar el envio.
  • Se comprueba el formato del correo con una expresion regular sencilla.
  • Se muestra un mensaje claro si falta informacion y se mueve el foco al campo invalido.
  • Se limpia el estado del formulario al escribir en cualquiera de los campos.
  • Se conecta el formulario con POST /api/contact mediante una solicitud JSON.
  • Se informa el estado del envio, se deshabilita temporalmente el boton y se limpia el formulario cuando se guarda el mensaje.
  • Se muestra un mensaje si falla la conexion o el servidor y se habilita nuevamente el boton.

Servidor y base de datos

  • Se agrego un servidor con Node.js y Express en server.js.
  • Al iniciar, crea automaticamente la base .data/portfolio.sqlite y la tabla contact_messages, con ID, nombre, correo, mensaje y fecha de creacion.
  • La ruta POST /api/contact valida los datos y los guarda usando una consulta preparada de SQLite.
  • Se limita el tamano de las solicitudes y se devuelven respuestas claras para datos invalidos o errores.
  • El servidor entrega la pagina y sus archivos estaticos para que el formulario y la API funcionen desde el mismo origen.
  • La carpeta .data/ se excluye de Git para no versionar los mensajes guardados localmente.

Configuracion y uso

  • package.json define las dependencias del servidor, el requisito de Node.js y los comandos npm start y npm test.
  • Se agregaron limites de caracteres a los campos y comentarios en espanol en server.js para explicar sus funciones principales.
  • El servidor se inicia con npm start y sirve el sitio en http://localhost:3000; se requiere Node.js 22.13 o superior.

Como ejecutar: instalar las dependencias con npm install, iniciar con npm start y abrir http://localhost:3000.

Verificacion realizada

  • npm test: las dos pruebas automatizadas pasan; verifican la pagina, el guardado de un mensaje valido y el rechazo de datos invalidos.
  • node --check server.js y node --check js/script.js: sintaxis verificada.
  • Se comprobaron los archivos HTML, CSS y JavaScript, incluidos los selectores y la estructura de la pagina.
  • Se comprobo el servidor en ejecucion: la pagina responde correctamente y la API guarda mensajes validos y devuelve un error para datos incorrectos.
  • git diff --check: no se encontraron errores de espacios en los cambios.

Los proyectos del portfolio siguen definidos en el HTML; la base de datos se utiliza unicamente para los mensajes de contacto.
